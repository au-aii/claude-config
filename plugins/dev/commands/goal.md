ゴールを受け取り、適切な既存入口へ振り分ける**薄いルーター**。実装ロジック・計画テンプレート・レビュー機構は一切持たない（全て既存資産へ委譲する。ADR 0007 / 0008）。

**引数:** ゴールの自然文（オプション: `--auto`）

## ステップ1 — ルーティング質問（最小限）

判定表の行が決まるまでの質問だけを行う（目安1〜2問）。**ゴール自体の深掘りはここでしない**（ステップ3の /grill-me 委譲に回す）。
リポの状態（PRD・`docs/` 永続ドキュメントの有無など）は質問せず Read / Glob で自分で確かめる。

## ステップ2 — ルーティング判定

| 観測されるゴールの特徴                            | 宛先            |
| ------------------------------------------------- | --------------- |
| リポに PRD / 永続ドキュメントが無い・ゼロから作る | /setup-project  |
| 影響範囲が読めない・複数ファイル横断・リスク高    | /asdd           |
| 既存パターンが明確な定型の機能追加                | /add-feature    |
| 実装は後で、計画ファイルだけ欲しい                | /setup-steering |
| 各段階で人間承認を挟みたい・分業したい            | /design         |

- 判定不能なら2択の質問を**1回だけ**行い、なお不明なら**安全側（/asdd）**に倒す
- ゴールが SDD の対象外（ノート作成・単発の調査・質問等）なら、その旨を伝えて通常の対話に戻る（無理にルーティングしない）

## ステップ3 — 承認ゲート（既定で必ず停止）

以下を提示して**停止し、承認を待つ**：

1. **宛先**と**根拠**（判定表のどの行に該当したか）
2. **想定手順**と**作られる計画成果物**（requirements / design / tasklist 等。ユーザーは実装前にこれらへ目を通せる）
3. **/grill-me の選択肢**（利用可能な環境のみ） — 重い宛先（/setup-project・/asdd・/design）では「先に /grill-me でこのゴールを審問する」を**推奨**として提示、軽い宛先（/add-feature・/setup-steering）では任意。/grill-me は common プラグインのコマンドのため、**存在しない環境（dev プラグイン単体の配布先等）ではこの選択肢を提示せず省略する**。審問した場合は、**結果を踏まえてこのステップ3の提示をやり直し、改めて承認を待つ**（審問でゴールの形が変わったらステップ2の判定からやり直す）。決定木の要約と未解決の分岐は委譲先の requirements 入力として引き継ぐ

**`--auto` の限定**: `--auto` が指定され、かつ宛先が /add-feature の場合**のみ**ゲートをスキップしてよい。他の宛先では `--auto` を無視して必ず停止する（設計判断系を無停止にしない）。

## ステップ4 — 委譲

承認された宛先コマンドの定義を Glob `**/commands/<宛先>.md` で解決して Read し（`~/.claude/commands/`・プロジェクトの `.claude/commands/`・プラグイン配置のいずれでも可）、**その手順に従う**。手順をこのファイルへ複製しない（ドリフト防止）。Issue 番号が分かっていれば委譲先へ引き継ぐ。

## ステップ5 — 出口の案内

委譲先の作業が完了したら、共通の出口として `/ship`（push→レビュー→PR→マージ）を案内する。

## 完了条件

- 委譲後は委譲先コマンドの完了条件に従う（/goal 自身の責務はルーティングと承認ゲートまで）
